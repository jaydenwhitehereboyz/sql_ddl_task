# Сравнение схем двух БД PostgreSQL

Сравнение структуры таблиц двух баз (`schema_compare_left` и `schema_compare_right`) и генерация DDL, который приводит правые таблицы к левым. Межбазовые запросы выполняются через расширение `dblink`.

## Файлы

| Файл | Где выполнять | Назначение |
| --- | --- | --- |
| `00_create_dbs.sql` | любая БД (например, `postgres`) | создание двух баз |
| `00_setup_left.sql` | `schema_compare_left` | расширение `dblink`, схемы и таблицы левой базы |
| `00_setup_right.sql` | `schema_compare_right` | схемы и таблицы правой базы |
| `task_1.sql` | `schema_compare_left` | задача 1: пересекающиеся таблицы и различия в полях |
| `task_2.sql` | `schema_compare_left` | задача 2: генерация DDL для приведения правых таблиц к левым |

## Тестовый стенд

| Левая база | Правая база | Что проверяет |
| --- | --- | --- |
| `rep.report` | `rep.report` | различия типов, длины/точности, NULL, комментариев; поле только слева; поле только справа |
| `rep.client` | `rep.client` | таблица без различий (не должна попадать в результат задачи 1, п. 2–3) |
| `rep.archive` | — | таблица только слева (не сравнивается) |
| — | `rep.log` | таблица только справа (не сравнивается) |
| `sales.orders` | `crm.orders` | **одноимённые таблицы в разных схемах** |

## Подготовка

1. Создать базы из `00_create_dbs.sql`.
   Каждую команду выполнять **отдельным запросом**: `CREATE DATABASE` нельзя выполнить внутри транзакции, а pgAdmin выполняет несколько команд одним блоком.
2. Выполнить `00_setup_left.sql` в базе `schema_compare_left`.
3. Выполнить `00_setup_right.sql` в базе `schema_compare_right`.

## Подключение dblink

Во всех вызовах `dblink` в `task_1.sql` и `task_2.sql` замените `***` на свои данные (без кавычек вокруг значений):

```sql
dblink('dbname=schema_compare_right user=ВАШЕ_ИМЯ_ПОЛЬЗОВАТЕЛЯ password=ВАШ_ПАРОЛЬ', ...)
```

Если сервер не на локальной машине или не на стандартном порту, добавьте `host=... port=...` в ту же строку.

## Запуск

Все запросы выполняются в базе `schema_compare_left`.

### Задача 1 — `task_1.sql`

Два запроса:

1. **Пересекающиеся таблицы** — таблицы, которые есть в обеих базах. Сопоставление идёт **по имени таблицы**, схемы выводятся отдельно (`left_schema`, `right_schema`) и могут различаться.
2. **Различия в полях** пересекающихся таблиц: тип (`type_diff`), NULL / NOT NULL (`is_null`), комментарий (`name_diff`). Формат: `левое значение\правое значение`. Поле выводится, если отличается хотя бы один из параметров.

### Задача 2 — `task_2.sql`

Генерирует DDL-команды, приводящие правые таблицы к левым. **Запрос ничего не меняет сам**: результат (столбец `ddl`) нужно скопировать и выполнить в базе `schema_compare_right`.

Команды упорядочены по шагам (столбец `step`):

1. `ADD COLUMN` — поля, которых нет справа;
2. `ALTER COLUMN ... TYPE` — изменение типа, длины, точности;
3. `SET / DROP NOT NULL`;
4. `COMMENT ON COLUMN`.

DDL строится с **правой** схемой, потому что выполняется в правой базе (например, `ALTER TABLE crm.orders ...` для левой `sales.orders`).

> При копировании результата из pgAdmin строки могут оказаться в двойных кавычках. Их нужно убрать перед выполнением: Preferences → Query Tool → Results grid → настройка кавычек при копировании, или «Найти и заменить» `"` на пустоту. Одинарные кавычки внутри `COMMENT` трогать не нужно.

## Проверка результата

Ожидаемый результат на тестовом стенде:

| Запрос | До применения DDL | После применения DDL |
| --- | --- | --- |
| Задача 1, запрос 1 | 3 строки: `client`, `report` (`rep`/`rep`), `orders` (`sales`/`crm`) | 3 строки |
| Задача 1, запрос 2 | 6 строк: 4 по `report`, 2 по `orders` | 0 строк |
| Задача 2 | 13 команд | 0 строк |

Порядок проверки:

1. Выполнить `task_1.sql` и `task_2.sql`, сохранить результат.
2. Выполнить сгенерированный DDL в `schema_compare_right`.
3. Повторно выполнить `task_1.sql` и `task_2.sql`: второй запрос задачи 1 и задача 2 должны вернуть 0 строк. Это значит, что структуры совпали.

## Допущения и ограничения

- Эталон — левая база.
- Сравниваются только таблицы, которые есть в обеих базах (типа `BASE TABLE`), системные схемы исключены.
- Таблицы сопоставляются по имени. Если одноимённая таблица есть в нескольких схемах одной базы, будет сформировано несколько пар.
- Поля, которые есть только справа, не удаляются (в стенде — `rep.report.extra`, `crm.orders.extra`).
- `ALTER COLUMN ... TYPE ... USING` может не выполниться, если в правой таблице есть данные, несовместимые с новым типом. `SET NOT NULL` не выполнится, если в столбце есть NULL.

## История изменений

**Одноимённые таблицы в разных схемах.** Изначально таблицы сопоставлялись по паре «схема + имя», поэтому, например, `sales.orders` и `crm.orders` не попадали в сравнение. Исправлено:

- задача 1 — сопоставление таблиц и полей по имени, схемы выводятся отдельными столбцами;
- задача 2 — поля правой таблицы берутся из схемы найденной правой таблицы, а DDL формируется с правой схемой;
- в стенд добавлены `sales.orders` / `crm.orders` для проверки этого случая.
